# HaplotypeCaller 为什么比 pileup 强，以及 QUAL 什么时候是假的

（编号 022 · 实测部分：1000G Phase3 chr22 / 5431 位点；GATK 未安装，调用流程为文档口径）

**要点一｜HC 强在「先组装再判定」**
pileup 调用器（bcftools mpileup、旧 UnifiedGenotyper）对对齐的每一列**独立**判基因型，直接信任比对器对每条读段的放置。在 indel 附近，这种放置是每条读段各自的贪心最优，不是位点一致的——同一个 indel 在不同读段里被放到不同位置，于是被系统性误表示。

HaplotypeCaller 丢弃局部对齐，在有信号区域做**局部 de-novo 组装**出候选单倍型，再把每条读段重新比对上去。indel 因此**只被表示一次**，在一个组装好的单倍型里。这是它在 indel 与复杂位点上胜出的机制原因。再往下，它对每个（读段, 单倍型）对用 PairHMM 对**所有**比对方式做积分（前向算法），而不是只取最优一条——在对齐本身不确定时，这才是统计上正确的加权方式。

**要点二｜GVCF 的 `<NON_REF>` 是队列可扩展的关键**
`-ERC GVCF` 在每个位置（变异与非变异）都记录「该位点为纯合参考」的置信度，并且每条记录都带一个符号等位 `<NON_REF>`（「任何尚未观测到的等位」），针对它计算 AD/PL。

这带来两个后果：一是**前向兼容**——某个变异即使在本样本看起来是参考，等别的样本发现它之后，仍能用 `<NON_REF>` 的证据在本样本里评估；二是**能区分「确证纯合参考」与「没数据」**，把参差的基因型矩阵「平方化」。再加上昂贵的组装只做一次，加第 N+1 个样本时只需重跑廉价的合并与基因分型——这就是 N+1 问题的解法。

顺带一提：GVCF 里连续的非变异位点会按 GQ 折叠成 homRef 区块，所以它不是每碱基一行。

**要点三｜QUAL 可能是假的（实测）**
文档给出 DRAGEN 模式的 QUAL 硬过滤切点是 **10.4139**（QUAL 更低的位点判为不可信）。用等价式在本数据上验证：

| 表达式 | 记录数 |
|---|---|
| `QUAL >= 10.4139` | 5431 / 5431 |
| `QUAL < 10.4139` | 0 条 |

**一条都没被滤掉**——因为这个 callset 的 QUAL 恒为 100（整合集把 QUAL 当统一占位值）。也就是说，在 QUAL 未被校准的 callset 上，按 QUAL 过滤是空转。真实项目里 QUAL 经过校准时这个阈值才有意义。

另外：本数据不含 `<NON_REF>`（0 条），说明它是联合基因型之后的**最终 VCF**，不是 GVCF 中间体——`<NON_REF>` 已经在基因分型阶段被消解成真实 ALT 了。

**结论**：HC 的价值在重组装与参考置信度模型；但拿到 callset 先查 QUAL 分布——恒定的 QUAL 意味着所有按 QUAL 的过滤都不起作用。
