# 023 · bioSkills 真实试用：joint-calling（联合基因型）

## 功能定位与适用范围

`joint-calling` 讲解**把逐样本 gVCF 联合基因分型为队列 callset**。

- **适用**：在联合基因型与「合并单样本 callset」之间做选择（后者永远是错的）；按队列规模与内存在 GenomicsDBImport 与 CombineGVCFs 之间选择；解决 N+1 问题；理解队列对低覆盖杂合位点的救援；处理跨越缺失的 `*` 星号等位与基因分型阶段的 GQ/PL 重算；按区间分片扩展到生物银行队列；在吞吐量考量下选择 DeepVariant + GLnexus。
- **不适用**：单样本调用（见 gatk-variant-calling）；VQSR/硬过滤机制（见 filtering-best-practices）。

## 属性表（本次环境）

| 项 | 值 |
|---|---|
| GATK / GLnexus | **均未安装** |
| 输入 gVCF | **无**（本数据为已联合基因型的最终 VCF） |
| 可真跑部分 | 联合基因型产物的特征核查（矩阵是否平方化、`*` 等位、缺失率） |
| 数据源 | 1000G Phase3 chr22（GRCh37/hs37d5），5431 条记录、2504 样本 |

## 治理原则：做联合基因型，永远不要合并 callset

联合基因型**不等于**合并单样本 VCF，混淆二者会静默损坏队列 callset。两个事实驱动下面所有决策：

- **联合基因型会救援低覆盖的杂合位点。** 证据跨样本借用：当一个携带者有一个可信变异时，队列等位频率会为**其他每一个样本**在该精确位点抬高贝叶斯先验，于是另一个只有 2–3 条支持读段的样本（逐样本判定会低于阈值）被救援成一个可信的基因型。这种「借用信息」机制在低覆盖下最强，也是队列 callset 比 N 个独立 callset 更灵敏的原因。
- **联合基因型产出平方化的矩阵**——每个变异位点上每个样本都有基因型。每个 gVCF 中的参考置信度 `<NON_REF>` 等位，使 GenotypeGVCFs 能在「另一个样本携带的位点」上区分**确证纯合参考**（`0/0`）与**无数据/未调用**（`./.`）。

由此得出决策：**永远不要把单样本 callset 用 `bcftools merge` 合并，就当缺失记录等于纯合参考。** 单样本 VCF 会省略那些该样本看起来是参考的位点，因此朴素的 merge 会用 `./.`（缺失）填充这些单元格，而**不是** `0/0`——一个真正纯合参考的样本与一个从未被评估的样本变得不可区分，下游的等位频率与关联检验随之出错。`./.` ≠ `0/0` 是承重的区别。要从 gVCF 做基因分型，让每个单元格都由证据而非假设填充。

## 成分拆解

### 1. 联合调用带来什么

- **共享证据带来的统计功效**：一个样本里只有 2 条 alt 读段的位点是边缘的、通常会被漏掉。若队列里另有 50 个样本在同一位点也各有 2 条 alt 读段，证据就是压倒性的，该变异显然是真实的。联合调用把这种「每样本微弱」的信号聚合成强队列级证据。
- **通过队列先验精化基因型**：个体基因型似然与队列等位频率作为贝叶斯先验结合。一个在常见变异位点（AF=0.3）上的杂合调用，比在无人携带的位点上的同样调用获得更多支持。该先验显著提升低覆盖样本的准确性。
- **一致的位点表示**：所有样本在相同位点被基因分型，适用处产生纯合参考调用。没有联合调用时，一个缺失的基因型是歧义的：它可能意味着纯合参考，也可能只是覆盖不足——「缺失即参考」这一假定是下游分析中假阴性的常见来源。
- **队列过滤资格**：VQSR 及其后继 VETS 作用于整个队列的变异分布，需要队列规模的变异计数——单个深 WGS 基因组可提供足够变异，但外显子变异稀少，因此约 30 样本的门槛适用于外显子/panel 而非 WGS。过滤本质上是一个队列操作，不是逐样本操作。

### 2. N+1 问题与 gVCF 的解法

朴素的联合调用在队列变化时重访每一个 BAM：加一个基因组就要重新调用全部 N 个。gVCF 工作流把昂贵的**逐样本发现**（局部组装 + PairHMM 似然，在 gVCF 中每样本只捕获一次）与廉价的**全队列基因分型**解耦。此后加入第 N+1 个样本只需生成那一个 gVCF，并重跑廉价的合并与 GenotypeGVCFs——现有 N 个样本的组装工作永不重复。gVCF 是可复用的中间体；GenomicsDB 工作区甚至可原地更新（`--genomicsdb-update-workspace-path`）。

### 3. 队列规模决策表

| 队列规模 | 方法 | 说明 |
|---|---|---|
| < 100 | CombineGVCFs 或 GenomicsDB | 两者皆可；CombineGVCFs 更易管理 |
| 100–10,000 | GenomicsDB + GenotypeGVCFs | 标准 GATK Best Practices；按染色体分片 |
| 10,000–100,000 | GATK Biggest Practices | 跨区间重度分片与并行 |
| > 100,000 | DeepVariant + GLnexus，或 Hail VDS | GATK 在此规模变得笨重；需要专用工具 |

### 4. GenomicsDBImport vs CombineGVCFs

| | GenomicsDBImport | CombineGVCFs |
|---|---|---|
| 存储 | TileDB 阵列后端上的 GenomicsDB 工作区；把以样本为中心的 gVCF 转置为以位点为中心的稀疏二维阵列（样本 × 位置） | 纯 Java 层次合并为单个组合 gVCF |
| 扩展性 | N 大时最优；以位点为中心的转置正是大规模下逐位点基因分型快的原因 | N 增长时失效——吃内存且慢；仅作为小队列的退路 |
| 可移植性 | 工作区不是普通 gVCF；须通过 `gendb://` 做基因分型 | 产出是普通 gVCF，可移植、可检视 |
| 增量 | 用 `--genomicsdb-update-workspace-path` 加新样本（实践中的 N+1 收益） | 无增量模式；对所有样本重跑 |
| 适用 | > 100 样本，按区间分片，生物银行规模 | < 100 样本，或简单性优先的小家系/三人组 |

**GenomicsDBImport 特有的内存地雷**：重活在原生 C/C++（TileDB）中运行，因此要把 JVM 堆（`-‑java-options -Xmx`）限制在内存的约 80–90%。过度分配 JVM 会使原生层缺内存，导致一个看起来与堆大小无关的原生 OOM。

### 5. GenotypeGVCFs 重算了什么（为什么它不是复制）

GenotypeGVCFs 从存储的逐样本 PL 向量（含 `<NON_REF>` 似然）在贝叶斯模型下**重新联合推导**基因型；它不是把逐样本基因型复制进一个更宽的文件。两个后果在读输出时很重要：

- **GQ 与 PL 是针对最终确定的队列等位集合重算的。** 一旦全队列的真实 ALT 等位已知，`<NON_REF>` 似然被重新分配到它们上面，PL 随之重算；GQ 则是两个最小 PL 之差。因此**一个样本在联合 VCF 中的基因型/GQ 可能与其单样本 gVCF 所暗示的不同**——这是救援机制在起作用，不是 bug。
- **等位频率先验来自 `--heterozygosity`**（期望 theta，人类约 0.001；在工具内确认）与 `--indel-heterozygosity`，把队列等位计数折进每个样本的后验。`--stand-call-conf`（约 30；在工具内确认）丢弃低于该 QUAL 的位点。

### 6. 多等位与跨越缺失的 `*` 等位

- **`--max-alternate-alleles`** 限制每个位点参与基因分型的 ALT 等位数（保留支持最多的；用 `gatk GenotypeGVCFs --help` 确认安装版本的默认值）。基因分型开销大致随 ALT 计数指数增长，因此 GATK 对其设限且不鼓励调高；`--max-genotype-count` 类似地约束基因型构型数。高度多等位的位点也是 GenotypeGVCFs 在大规模下可能突破极大内存的地方。
- **`*` 跨越/重叠缺失等位**（VCF 4.3 保留）出现在「落在某些样本所携带的上游缺失内部」的变异位置。它的含义是「对于携带该上游缺失的样本，这些碱基被删除/不存在」——既不是参考，也不是本地 ALT。这类样本被判为 `*/A` 或 `*/*`，这正确地避免了把缺失携带者在内部位点上误判为纯合参考。下游工具必须对它特殊处理：VEP/SnpEff 没有可预测后果的 ref/alt 序列，而 `bcftools norm` 的分解经常会拆分或过滤掉它，因此它是联合基因型之后注释意外的常见来源。

### 7. 过滤是队列操作

过滤联合 VCF 是全队列步骤，不是逐样本步骤，且必须**在联合基因型之后**运行。VQSR（及其 GATK 后继 VETS）把模型拟合到队列范围的位点注释分布——VQSR 的高斯混合需要足够的变异与足够的真值资源重叠才能收敛，这正是它在单个外显子或小 panel 上不可靠的原因。

| 队列 | 过滤 | 原因 |
|---|---|---|
| 单个深 WGS，或联合队列（约 30+ 外显子） | VQSR，或 VETS | 有足够变异拟合稳定的多变量模型；一个 WGS 基因组提供数百万位点，但外显子变异稀少，故约 30 样本门槛针对外显子/panel 而非 WGS；若已输出等位特异注释则传 `-AS`，使多等位位点上每个等位被独立过滤 |
| 单个外显子、基因 panel，或变异太少 | 硬过滤 | GMM 在过少变异上不收敛；改用固定的每注释阈值 |

### 8. 联合调用中的批次效应

联合基因分型缓解了大部分批次效应，因为它同时重估所有样本的基因型似然，对全队列分布重新校准质量分数。但某些批次效应会穿透联合调用，因为它们影响的是底层读段数据而非基因分型模型：不同文库构建方案（PCR-free vs PCR-based 产生不同的重复与错误谱）、不同捕获试剂盒（外显子靶向区域不同，交集外的位点在某些批次中系统性缺失）、显著不同的覆盖分布（10× WGS 与 30× 混合会在杂合位点产生系统性不同的基因型质量）、不同参考基因组版本（混合 GRCh37 与 GRCh38 比对无效；所有样本必须用同一参考）、混合 WGS 与 WES（覆盖谱根本不同）。缓解办法：所有样本走完全相同的上游流程；若批次不可避免，在下游关联或差异分析中把批次作为协变量纳入。

### 9. DeepVariant + GLnexus 替代路线

GLnexus 是一个可扩展的 gVCF 合并/联合基因分型引擎，随样本加入**增量式**增长，避免了 GenomicsDBImport + GenotypeGVCFs 路径所需的全队列重处理。Yun 等针对 DeepVariant 输出调整了质量阈值，优化后的预设随 GLnexus v1.2.2+ 发布为 `DeepVariantWGS`（全基因组）与 `DeepVariantWES`（全外显子）。

| 指标 | DeepVariant + GLnexus | GATK（VQSR） |
|---|---|---|
| SNP F1 错误 | 0.07% | 1.23% |
| Indel F1 错误 | 1.14% | 2.92% |
| 队列孟德尔违规率 | 1.7% | 5.0% |
| chr22 队列合并时间（2504 样本） | 0.84 h | 6.83 h |
| 队列 gVCF 占用 | 2.20 TB | 15.16 TB |

这些是一个研究在特定版本/覆盖度下的数字，应视为代表性而非普适。吞吐差距（GLnexus 合并约快 8 倍，DeepVariant gVCF 磁盘占用约小 7 倍）是大型 DeepVariant 队列使用 GLnexus 而非 GenotypeGVCFs 的实际原因。

## 本次实测（可真跑部分）

**① 平方化矩阵核查（联合基因型的产物特征）**

```
bcftools stats -s - chr22_slice.vcf.gz | grep '^PSC'
样本数 = 2504 ；缺失基因型总数 = 0 ；每样本均值 = 0.00
```

**2504 个样本、5431 个位点上没有任何缺失基因型**——这正是联合基因型「平方化」的产物特征：每个变异位点上每个样本都有由证据填充的基因型（`0/0` 或携带型），而不是 `./.`。作为对照，若在单样本 VCF 上做 `bcftools merge`，缺失的记录会以 `./.` 填充而不会被当作 `0/0`（该语义在 019 中已实测）。

**② `*` 跨越缺失等位核查**

本数据中 `ALT == "*"` 的记录数为 **0**。原因：本数据是 1000G Phase3 的整合发布集，跨越缺失等位已在发布前被处理/规范；`*` 主要出现在 GATK 联合基因型的原始产出中。故本次无法实测 `*` 等位对注释工具（VEP/SnpEff）与 `bcftools norm` 分解行为的影响。

**③ 单样本 vs 联合的基因型救援**

需要同一批样本的两套 callset（逐样本调用 + 联合调用）才能对比，本环境无 BAM 且 GATK 未安装，未做真跑。

## 实践要点

- **永远用 gVCF 联合基因型，不要 `bcftools merge` 单样本 callset**：缺失记录是 `./.` 而不是 `0/0`，会把等位频率与关联检验搞错。
- **GenomicsDBImport 的 JVM 堆控制在内存的 80–90%**：重活在原生 TileDB 层，堆给多了会引发看似无关的原生 OOM。
- **GenomicsDB 无样本替换**：只能加不同名的新样本，改一个样本就要重建工作区；区间在导入时锁定，增量更新不能扩展区间。增量添加前备份工作区。
- **联合 VCF 里出现 `*/A`、`*/*` 是预期行为**，但注释前须特殊处理或拆分 `*` 记录。
- **过滤必须在联合基因型之后、且是队列级操作**；外显子/panel 不足约 30 样本时退回硬过滤。
- **混合 GRCh37 与 GRCh38 比对无效**；所有样本必须同参考、同上游流程。

## 小结

joint-calling 的核心是「用 gVCF 的参考置信度把每个单元格由证据填满，而不是由假设填充」。本次受环境限制未能真跑 GATK/GLnexus 流程，但完成了一项可验证的产物特征核查：**2504 样本 × 5431 位点上缺失基因型为 0**，证实本数据确实是联合基因型产出（平方化矩阵），而非单样本合并的结果——后者会留下大量 `./.`。同时确认本数据不含 `*` 跨越缺失等位（发布集已处理），该等位对下游的影响未能实测。
