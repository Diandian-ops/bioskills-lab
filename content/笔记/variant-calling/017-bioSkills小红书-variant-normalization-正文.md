# 同一个变异，为什么不同软件报出来的位置不一样？

把 VCF 做「归一化」之前，很多人以为 caller 给的坐标就是最终坐标。其实同一个 indel 在重复区里可以写出好几种合法位置，跨软件一比对就「对不上」——这不是 bug，是表示方式没统一。

本次用 1000 Genomes（chr22，真实数据，2504 样本）实测了 bcftools norm 的几个关键行为：

**要点一｜多等位一定要拆**
真实位点 `22:17020038 C→A,T`，AF 是 `0.0004 / 0.0773`（Number=A，两个 ALT 共用一个向量）。`bcftools norm -m-` 拆成两条二等位记录，每条各带自己的 AF。PLINK、ClinVar 比对都要求二等位，不拆就直接报错或读错值。

**发现 2｜左对齐 + 简约 = 幂等**
「归一化」= 左对齐（把 indel 滚到重复区最左）+ 简约（去掉冗余共享碱基），两者都满足才叫范式化，且对已归一化的结果再跑一次不会变。本次 5431 条记录 norm 前后 md5 完全一致。

**要点三｜REF 不匹配会静默报错**
用错参考（或基因组版本不对）时，默认 `-c e` 会直接非零退出并指明「REF_SEQ:'C' vs VCF:'G'」。别用 `-c w` 把它压成警告蒙混过关——先确认参考到底对不对。HGVS 的 3' 规则和 VCF 的 5' 左对齐方向相反，同一个缺失的「位置」天然可能不一致，HGVS 该交给注释引擎生成，别手算。

**结论**
跨 caller、跨队列、做数据库注释或合并前，先用「同一工具 + 同一参数 + 同一参考」做归一化；拆分有损（丢失复合杂合相位），能用二等位就用二等位，必要时最后再 `-m+` 还原。
