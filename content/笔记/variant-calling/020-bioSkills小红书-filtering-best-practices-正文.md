# 变异过滤：先看 QUAL 有没有信号，再看 Ti/Tv

（编号 020 · 真实数据：1000G Phase3 chr22 / 2504 样本 / 5431 位点）

**要点一｜QUAL 可能是假的**
拿到 callset 先查 QUAL 分布。本次实测：5431 条记录的 QUAL 唯一值只有 **1 个**（全是 100），FILTER 也全是 PASS。1000G 整合集的 QUAL 是合并后的统一占位值——对它做 `QUAL >= 30` 过滤，**一条都不会少**。真实项目里遇到这种文件，位点质量过滤得换维度：DP、AF、变异类型。

**要点二｜过滤后 Ti/Tv 会变，这是校验器**
按 AF 过滤，随稀有变异被剔除，Ti/Tv 从 **1.95 升到 2.10**，进入 WGS 期望带（2.0–2.1）：

| 过滤条件 | 保留记录数（条） | Ti/Tv 实测值 |
|---|---|---|
| 全部（未过滤） | 5431 条 | Ti/Tv = 1.95 |
| AF≥1e-3 | 2147 条 | Ti/Tv = 2.00 |
| AF≥1e-2 | 949 条 | Ti/Tv = 2.10 |

原因：低频变异里随机测序错误占比更高，而随机错误的 Ti/Tv 约为 0.5，远低于真实变异的 2.0 左右水平，混入后把整体比值拉低。反向用法同样成立：若某次过滤后 Ti/Tv 不升反降，说明过滤器正在优先删除真实的转换——阈值校准有误。

**要点三｜纯合 alt 位点最容易被静默删光**
MQRankSum、ReadPosRankSum 这类秩和检验比较的是 ref 读 vs alt 读，**只在杂合位点有定义**。纯合 alt 没有 ref 读，该值是缺失（`.`）。GATK 的规则是「值存在且违规才过滤」——缺失即通过。手写 bcftools 必须显式加守卫，否则纯合 alt 会被清空：

`bcftools filter -i '(INFO/MQRankSum >= -12.5 || INFO/MQRankSum = ".")' ...`

另外：SNP 和 indel 必须分开过滤（indel 的 FS 放宽到 200、ReadPosRankSum 收紧到 -20）；过滤优先用软过滤 `-s 标签`，保留 FILTER 列便于回溯。

**结论**：过滤不是「指标越严越好」，而是按数据规模选方法、位点/基因型两层分开做、过滤后回看 Ti/Tv 验证。
