# GTF 转 GFF3，CDS 差 3 个碱基

（编号 049 · 数据：seed=49 合成注释集，1 条 2,000,000 bp 染色体，8 个基因 / 9 条转录本 / 29 个外显子；gffread 0.12.9 + bedtools v2.31.1 真跑）

**封面卡｜同一份基因模型，GTF 版 CDS 比 GFF3 版统一短 3 nt——9/9 条转录本，1 nt 都不差**

**发现一｜注释文件是树不是表：属性键和 ID 规则随来源变**

同一份模型写两版文件：GTF 版用 gene_type 属性、ID 带版本号（60 行版本化 ID）；GFF3 版用 gene_biotype、ID/Parent 层级、0 行版本号。九列结构两版都成立，属性键却完全不同——按 biotype 筛选拿错键名，返回空集且无任何告警。seqid 同理：chr1 vs 1 字符串交集为 0 个，naive join 60 行对上 0 行。还有个容易忽略的转换行为：gffread -T 把 GFF3 转 GTF 后，gene 行从 8 条变 0 条、ID 版本号被剥掉，下游按 gene 聚合的步骤直接受影响。

**发现二｜CDS 恰差 3 nt，蛋白却 9/9 一致**

GTF（Ensembl/GENCODE 约定）的 CDS 不含终止密码子，GFF3（GenBank 风格）包含。实测 9/9 条编码转录本：gffread -x 提取的 CDS 长度，GFF3 版恰好比 GTF 版多 3 nt；而 gffread -y 翻译出的蛋白逐残基一致——工具知道这套约定，会正确处理。手工拼接坐标或跨来源比较长度时才会中招：CDS 差 3 nt、蛋白差 1 个残基，先对约定表，不是坐标 bug。

**发现三｜start-1 只动 start：每外显子错 1 bp，序列级现形**

GTF 转 BED 的正确口径是 start 减 1、end 不变。把外显子 BED 序列按转录方向拼接，与 gffread -w 的转录本 FASTA 逐碱基比对：9/9 条全等（含负链）。故意把 end 也减 1（过度校正）作对照：29 个外显子合计丢 29 bp，每条转录本短 2-5 bp。这种位移在覆盖度、overlap 分析里完全看不出来，一旦进入翻译就是移码。

**结论**：处理注释文件后做三件程序化检查——seqid 与 ID 两组键求交集、序列级比对验证坐标转换、长度差先对终止密码子约定表。本次全部数字来自固定 seed 的可复现脚本；审计口径独立于数据生成器，连生成器自己的一个负链坐标错误都是被审计抓出来的。
