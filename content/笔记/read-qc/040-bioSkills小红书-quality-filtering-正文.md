# 丢整条还是剪尾巴？质量过滤先分清两种动作

（编号 040 · 数据：20,000 条模拟 reads × 150 bp，质量从 5' 端 Q37 衰减到 3' 端 Q12，另含 8% 全局低质量亚群；fastp 1.3.6 / cutadapt 5.2 / trimmomatic 0.41）

**封面卡｜丢弃只提 1.24 个 Q，修剪能提约 5 个 Q —— 差别全在读长**

**发现一｜丢弃（filter）与修剪（trim）不可互替**

同一批 20,000 条 reads，两种操作给出两种形态：

- fastp 逐条过滤（-q 20 -u 40 -l 36）：丢 1,643 条，保留率 91.78%；留下的 reads 长度不变（150 bp），平均 Q 只从 24.73 升到 25.97 —— 坏尾巴原样留在读上。
- 三种窗口修剪（fastp --cut_right / cutadapt -q 20 / trimmomatic SLIDINGWINDOW:4:20）：保留率同为 92.08%，平均 Q 升到 29.97-30.17，但平均读长缩到 105.8-108.0 bp，碱基少拿约三分之一。

判断依据是质量分布的形态：部分 read 全程差（双峰）就整条过滤，所有 read 尾部差（逐 cycle 衰减）就窗口修剪。两种问题在本次数据里并存，所以两种操作的效果差被直接测了出来。

**发现二｜三种算法同设 Q20 阈值对比：结果几乎重合**

滑动窗口（trimmomatic）、BWA running-sum（cutadapt）、fastp cut_right 三种算法保留的 reads 完全一致：18,416 条（92.08%），修剪后平均 Q 最大差 0.2，平均读长差 2.2 bp。工具之间的差异小于阈值选择的影响，先认真选 Q 值，再谈换工具。

**发现三｜MAXINFO 修剪最狠，却 0 条被丢**

trimmomatic MAXINFO:40:0.5（长度-质量自适应平衡）把平均读长压到 102.2 bp，五组里最短；质量最差的 1,584 条 reads 被修到 36-60 bp 区间，但没有一条跌破 MINLEN:36，20,000 条全部保留，平均 Q 仍有 29.37。对照组：其余三组窗口修剪各丢 1,584 条（占 7.92%），淘汰动作全部由 36 bp 长度门槛完成 —— 「修剪必须配最小长度门槛」这句话，就是这些被丢 reads 的去向。

**结论**：质量过滤第一步先看问题形态——坏 read 亚群用整条过滤（fastp -q/-u/-e），坏尾用窗口修剪（Q20 起步），修剪之后必须接长度门槛（MINLEN / -l / -m）。文献口径一致：轻修剪是默认，激进修剪（Q25-30 以上）会让超过 10% 基因的表达估计偏移，也会劣化 de novo 组装。
