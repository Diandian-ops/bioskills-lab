## launch_console.bat 双击报错修复（20:29）
- 现象：用户双击 `output/_patch/launch_console.bat` 报「系统找不到指定的路径」×2 + `'le' 不是内部或外部命令」——`'le'` 是 cmd 把 LF 行尾 .bat 错误切分出的诡异 token，不是脚本真有此命令。
- **根因**：`launch_console.bat` 是 **LF 行尾（Unix 格式）**，而 Windows `cmd.exe` 对 LF 行尾的 .bat 解析异常（多行 `if/else`、管道、`start` 参数全部错位），这是 Write 工具默认产出 LF 所致。所有关键路径（managed python 3.13.12 / serve_console.py / index.html）实际都存在，8899 服务也一直在跑（PID 15716），所以服务本身没问题，只是 bat 崩在「打开浏览器」那步前。
- **修法**：用 managed python 以 `newline="\r\n"` 重写 bat（已确认首字节 `40 65 63 68 6f 20 6f 66 66 0d 0a` = `@echo off\r\n`）；端口检测改用 python `socket.connect_ex` 而非 `netstat`（去掉命令依赖、更通用）；echo 提示改纯英文避免编码风险。
- **重要约定**：本仓库任何 `.bat` 文件必须用 **CRLF 行尾** 写入（Write 工具默认 LF，会踩坑）；通过 python `open(path,'w',newline='\r\n')` 或 PowerShell 写最稳妥。`.bat` 里避免中文 echo（编码风险），路径/变量用绝对路径。
- 现状：8899 服务（http.server 实时读磁盘）伺服的就是磁盘最新版发布台（侧栏纯标题、Markdown 文档 tab、API 设置已并入 AI 区均已确认）；用户双击 bat 修好后→检测端口已监听→直接 `start URL` 打开浏览器到 `http://127.0.0.1:8899/xhs-site/xhs-console/index.html`。也可直接双击 `output/xhs-site/xhs-console/index.html`（file://，无服务依赖，最新版）。
